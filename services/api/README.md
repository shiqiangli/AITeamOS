# AITEAMOS API Server

The API server exposes the workspace-backed product surface used by the dashboard.

Current greenfield responsibilities:

- Load and validate `.aiteamos` workspace manifests.
- Build SQLite/vector-derived indexes from workspace files; derived cache tables may be destructively rebuilt.
- Serve Projects and Employees backed by TeamMember, Assignment, Task, Run, Review, Memory, Skill, Permission, Automation, AutomationRun, MemberActivity, GitActivity, GitActivityImportReceipt, GitActivityCorrelationReview, Connector, ModelProfile, BudgetPolicy, and Artifact manifests.
- Expose task execution readiness through `GET /workspaces/{wsId}/tasks/queue` so the dashboard can prioritize missing member, assignment, execution profile, model, active run, stalled run, and review-ready work.
- Expose member-centric run launch plans through `GET /workspaces/{wsId}/tasks/{task_id}/launch-plan`.
- Expose generated context previews through `GET /workspaces/{wsId}/runs/{run_id}/context-preview`; context is resolved from member identity, assignment contract, permissions, memory bindings/grants, handoffs, docs, source excerpts, model, and budget policy, with structured source decisions for inclusion, exclusion, dedupe, snippets, and budget buckets.
- Expose existing stored context manifests through `GET /workspaces/{wsId}/runs/{run_id}/context-manifest`.
- Expose member/assignment-centric model and worker gates through `GET /workspaces/{wsId}/runs/{run_id}/model/readiness`, `GET /workspaces/{wsId}/runs/{run_id}/model/policy`, `GET /workspaces/{wsId}/runs/{run_id}/worker/readiness`, and `GET /workspaces/{wsId}/runs/{run_id}/worker/authorization`.
- Expose global and projected read surfaces for members, project contributors, assignments, member activity, git activity, git activity import receipts, memory stores/entries/bindings/grants/proposals, automations, skills, permissions, permission explanation, and member/project/assignment scoped permission governance.
- Expose `ProductUser`-backed session projection through `GET /session`; ProductUser manifests map dashboard principals to TeamMembers and admin/viewer roles while API auth accepts only configured token environment variables, never raw secrets from workspace files.
- Expose hardened ProductUser browser sessions through `POST /session/login`, `POST /session/renew`, and `POST /session/logout`: the cookie stores a signed expiring envelope, not the raw ProductUser token, unsafe cookie-backed mutations require `X-AITEAMOS-CSRF`, and `AITEAMOS_ENV`, `AITEAMOS_PUBLIC_URL`, `AITEAMOS_SESSION_COOKIE_SECURE`, and `AITEAMOS_SESSION_COOKIE_SAMESITE` drive environment-aware `Secure` / `SameSite` attributes.
- Admit local Git metadata through `POST /workspaces/{wsId}/git-activity/imports/admit-local-scan` as a `needs-review` `GitActivityImportReceipt` only; this path redacts sensitive refs, dedupes repeated scans, stores no raw provider payload, and does not create GitActivity.
- Admit GitHub/GitLab webhook or provider-sync metadata through `POST /workspaces/{wsId}/git-activity/imports/admit-provider-event` as a `needs-review` `GitActivityImportReceipt` only; this path stores payload digest, sanitized refs, hashed provider actor/repository/url metadata, and normalized activity type without retaining raw payload or creating GitActivity.
- Explain connector-scoped Git import policy through `POST /workspaces/{wsId}/git-activity/imports/policy/explain`; this read-only endpoint evaluates repository/installation allowlists, protected refs, actor-to-member mappings, connector health requirements, and dedupe intent without writing receipts or activities.
- Preview Git import receipt correlation through `GET /workspaces/{wsId}/git-activity/imports/correlation-preview`; this read-only endpoint groups receipts by PR/external id/ref/commit/payload digest and flags force-push, squash/merge, and multi-event risks without writing GitActivity.
- Record reviewed Git import correlation decisions through `POST /workspaces/{wsId}/git-activity/imports/correlations/review`; this writes a `GitActivityCorrelationReview` only, requires human or hybrid authority for approval, and does not mutate receipts, create GitActivity, approve memory, write growth records, or change permissions.
- Promote approved Git import correlation reviews through `POST /workspaces/{wsId}/git-activity/imports/correlations/{review_id}/promote`; this creates at most one `GitActivity`, links all selected receipts to it, updates the review with imported activity evidence, and rejects partial or cross-linked groups to avoid double-counting.
- Promote reviewed Git import receipts through `POST /workspaces/{wsId}/git-activity/imports/{receipt_id}/promote`; this path requires human or governed service review, explicit member/assignment mapping, and effective permission checks before writing linked GitActivity.
- Normalize permission actions for file, Bash, web/network, external MCP, environment-variable, connector-subscope, and artifact-store retention/redaction operations before they enter PermissionRequest/PermissionGrant approval flows.
- Expose generic PermissionRequest initiation for denied worker authorization and AutomationRun permission decisions through `/workspaces/{wsId}/runs/{run_id}/permission-request` and `/workspaces/{wsId}/automations/runs/{run_id}/permission-request`; these endpoints only write pending requests and never approve grants or execute work.
- Preserve typed decision-audit provenance in permission, review, and automation responses so dashboards can distinguish human approval, digital recommendation, service policy enforcement, and system lifecycle checks.
- Expose Automation manifests and AutomationRun control-plane records through automation create/list, dry-run, trigger, scheduler, and queued-run execute endpoints. Automation creation writes only configuration, including dashboard-created scheduler presets such as GitActivity retention sweeps; execution re-checks permissions and may create human reminders, connector-failure reminders, draft task plans, linked Task/Run records, or governed GitActivity evidence lifecycle updates, but it still does not run worker code as a side effect.
- Expose connector/provider operations health through connector health checks, provider delivery receipts, explicit and automation-owned failure reminder routing, repeated-failure review-request escalation, checklist-based escalation resolution, resolved-evidence suppression, suppression/re-routing explanation fields, read-only remediation suggestions with proposed TaskPlan payloads, a reviewed TaskPlan submit endpoint with permission/evidence freshness checks, submitted-remediation TaskPlan projection, reviewed TaskPlan acceptance into ordinary Tasks, materialized remediation Task projection with queue/launch readiness, reviewed remediation Run creation through the ordinary Run path, remediation Run follow-through projection with model/worker/authorization blockers, PermissionRequest/PermissionGrant outcome state, and next control-plane actions, remediation PermissionRequest initiation for denied Run actions, projection into Project/Employee/Reviews/Knowledge Health views, and retention cleanup endpoints that archive old manifests in place without deleting replay or audit evidence. Dashboard remediation prefill remains local preview state until the submit endpoint writes a normal draft TaskPlan with connector remediation lineage and decision audit; Run launch, follow-through projection, and permission-request initiation do not start worker execution or approve grants.
- Expose audited member collaboration surfaces through `GET /workspaces/{wsId}/member-messages`, `GET /workspaces/{wsId}/handoffs`, `GET /workspaces/{wsId}/retrospectives`, `GET /workspaces/{wsId}/collaboration/overview`, AskForHelp/ReviewRequest/resolve/retrospective write endpoints, and member-centric MCP tool endpoints under `/mcp/tools/*`.
- Create team retrospectives as pending learning: `POST /workspaces/{wsId}/retrospectives` and MCP `create_retrospective` write a `TeamRetrospective` plus pending `MemoryProposal`, never approved memory.
- Expose read-only retrospective aggregation through `GET /workspaces/{wsId}/retrospectives/suggestions` and MCP `suggest_retrospectives`; suggestions return candidate payloads and evidence but do not mutate `.aiteamos`.
- Keep durable write APIs dashboard/API-first; MCP/tool writes can create journals, events, pending memory proposals, messages, handoffs, and review patches, but cannot approve memory, close runs, merge code, or mutate policy.

The API must treat the workspace files as source of truth. Database rows are derived state.
